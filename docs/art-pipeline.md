# Art pipeline: Blender

**Decision (2026-11-13):** Use Blender for the fighters' art, driven by Python scripts.

## Plan
1. **Models:** start from free CC0 low-poly characters (Quaternius) instead of modeling from scratch. See `art/models/README.md`.
2. **Gear variants by script:** `art/blender/make_sprites.py` imports each fighter, tints its materials for each gear item (Gold Armor, Flame Bow, Storm Staff, …) and renders a transparent PNG of every combination into `art/renders/`.
3. **First in-game use: 2D sprites.** The game shows the rendered images instead of emoji. The game code stays simple, and the art still looks 3D.
4. **Stretch goal: real-time 3D.** Load the same models in the browser with Three.js (glTF format) and play their built-in animations. Only after accounts, saving and the dashboard work.

## Why Blender
- Gear unlocks need visible variants; a script makes all of them at once and can be rerun when items change.
- Free, and exports glTF for a later Three.js version.
- The script lives in the repo, so the art can be regenerated by anyone.

## Risks and fallbacks
| Risk | Fallback |
|---|---|
| Blender's learning curve eats build time | Keep the emoji/colored-card look from the prototype |
| Tinting looks flat or ugly | Tint only some materials (armor, not skin), or recolor by hand in Blender for 3–4 key items |
| Free models don't match each other in style | Use one pack for all three fighters |
| Character animation (sword swing, bow draw) is too slow to make | Use the animations that ship with the CC0 models, or simple slide/bounce motion coded in the game |
| 3D files make the game slow to load | Stay with 2D sprites |

## How to run
From the repository root, with Blender installed in Applications:

```
/Applications/Blender.app/Contents/MacOS/Blender --background \
  --python art/blender/make_sprites.py -- --models art/models --out art/renders
```
